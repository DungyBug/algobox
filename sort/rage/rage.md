# Поразрядная сортировка с слиянием

###### RAdix + merGE = Rage sort

Это модификация алгоритма поразрядной сортировки `radix sort`. Его преимуществом является улучшенная утилизация кэшей процессора за счёт использования сортировки слиянием `merge sort` на завершающих этапах, поскольку оригинальный алгоритм очень плохо кэшируется на больших размерах массивов.

### Краткий механизм работы

Запустим алгоритм сортировки слиянием. На этапе, когда мы разделили подмассив на два длины $$\le k$$, мы останавливаем разделение и запускаем поразрядную сортировку в них. После этого мы сливаем полученные отрезки, как в стандартном `merge sort`.

$$k$$ подбирается таким образом, чтобы подмассив этого размера полностью или почти полностью помещался в кэше процессора. Таким образом, `radix sort` не теряет в скорости и сортирует быстрее обычного `merge sort`.

В данной реализации $$k = 2^{17} = 131072$$

### Обзор

| Характеристика | O                                  |
| -------------- | ---------------------------------- |
| Сложность      | $$\mathrm{O}(nw\mathrm{log}(nw))$$ |
| Память         | $$\mathrm{O}(n)$$                  |

где

- n - размер массива
- w - количество проходов ( в данной реализации это количество байт в ключе )

Использование такое же, как и у `radixSort`:

```cpp
#include <random>
#include "radix.hpp"

// Функция-конвертер, которая принимает на вход элемент и записывает
// в `key` его числовой ключ ( в данном случае это сам элемент )
void u32toKey(uint32_t& element, void** key, uint32_t *keylen) {
    (*key) = (void*)&element;
    (*keylen) = sizeof(uint32_t);
}

uint32_t testArray[1000];
uint32_t outArray[1000];

for(uint32_t &value : testArray) {
    value = rand() & 0xff;
}

// Последний аргумент ( false ) говорит функции, чтобы ключи, созданные
// u32toKey не освобождались из памяти. Этот параметр нужен, если
// функция-конвертер выделяет новую память, что может быть нужно для
// более сложных типов данных
rageSort(testArray, testArray + size, outArray, u32toKey, false);

// теперь outArray хранит отсортированную копию testArray
```

Поскольку алгоритм включает в себя сортировку слиянием, можно указать компаратор:

```cpp
rageSort(
    testArray, testArray + size, outArray,
    u32toKey,
    false,
    // std::less используется в качестве компаратора по умолчанию
    std::less<uint32_t>())
```

### Статистика

На `uint32_t` `rage sort` показывает следующие результаты ( в секундах ):

| Размер массива | rageSort | radixSort | std::sort |
| -------------- | -------- | --------- | --------- |
| 10             | 0.000001 | 0.000001  | 0.000000  |
| 100            | 0.000002 | 0.000002  | 0.000005  |
| 1'000          | 0.000011 | 0.000011  | 0.000082  |
| 10'000         | 0.000123 | 0.000118  | 0.001062  |
| 100'000        | 0.002429 | 0.002351  | 0.012800  |
| 1'000'000      | 0.030535 | 0.033757  | 0.150556  |
| 10'000'000     | 0.332415 | 2.222634  | 1.722028  |
| 100'000'000    | 3.566252 | 28.370103 |           |

На 10'000'000 у `radixSort` просадка производительности, вызванная частыми промахами кэша процессора. Это показывает главный минус данной реализации ( и, возможно, самого алгоритма в целом ), для решения которой был создан `rageSort`.
_Стоит ометить, что на чистом archlinux просадка производительности у radixSort **не наблюдалась**, однако она была всё ещё **ниже** производительности rageSort в ~1.5-2 раза._

Замеры проводились на следующей конфигурации:

| Компилятор | MinGW (GCC) 13.1.0         |
| ---------- | -------------------------- |
| ОС         | Windows 10                 |
| Процессор  | Intel Core i7 7740X 4.3Ghz |
| L1 кэш     | 128kb                      |
| L2 кэш     | 1mb                        |
| L3 кэш     | 8mb                        |
